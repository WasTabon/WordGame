# WordGame — Итерация 11: Big Dictionary (валидация по большому словарю)

## Что сделано

Валидация слов теперь использует **большой словарь** (466k+ слов из твоего `words.txt`). Генерация поля остаётся быстрой — продолжает использовать маленький placement pool (401 слово).

### Архитектура: два словаря
- **Placement pool** (`word_list.txt`, 401 слово) — используется `BoardGenerator` для укладки слов на поле. Маленький → генерация быстрая. Не меняется.
- **Validation set** (`words.txt`, 466k слов) — используется `WordValidator` для проверки слов, которые собирает игрок. Большой → можно собирать любые английские слова.

Игрок может **найти слово, которое не было уложено генератором**, если оно есть в большом словаре. Например, поле сгенерировано из 12-15 простых слов, но игрок собирает `STARING` или `ENVELOPE` через буквы на доске → засчитается.

### Lazy loading + preload
- Большой словарь загружается **один раз** при первом обращении (через `HashSet<string>` для O(1) lookup)
- Чтобы не было freeze на первом слове игрока, `MainMenuUI` запускает `Dictionary.Preload()` через Coroutine при загрузке главного меню
- Время загрузки 466k слов ≈ 500-1000ms на типичном мобильном устройстве, происходит параллельно с анимацией меню
- Логи в Console: `[Dictionary] Loaded 466k validation words in 750ms.`

### Производительность и память
- 466k слов в HashSet<string> ≈ **30-40 MB RAM** (60 байт на запись с overhead)
- В APK добавится ~5 MB (раз сжато ~2 MB)
- Загрузка происходит на coroutine — без блокировки UI
- Lookup `IsValidWord("STARE")` за < 0.001ms (HashSet hash + compare)

### DeadlockDetector — компромисс
Детект тупика после собранного слова **продолжает использовать placement pool** (401 слово), а не большой словарь. Причина: перебор 466k слов для каждой стартовой клетки = непрактично по времени (миллионы DFS-проверок).

Trade-off: иногда может возникнуть game over («NO MORE WORDS»), когда теоретически из большого словаря ещё можно было что-то собрать. Но это редкая ситуация — placement pool покрывает 90%+ типичных слов 3-5 букв.

## Установка

1. **Распаковать архив поверх проекта** — добавит 3 .cs файла и 1 editor-скрипт.
2. **Положить твой `words.txt`** (466k слов) в `Assets/WordGame/Resources/`
   - Один формат: одна слово на строку, A-Z (case-insensitive)
   - Если откуда-то скачивал и слова с дефисами/апострофами — они отбросятся
3. **Запустить editor-скрипт:** `WordGame > Setup Big Dictionary (Iteration 11)`
   - Скрипт проверит файл, посчитает валидные слова, выдаст лог
   - Импортирует `words.txt` как TextAsset
4. `MainMenu.unity` → Play.

### Если words.txt не положен
Editor-скрипт выдаст красный лог-error с инструкциями. В игре `Dictionary` будет fallback на placement pool (401 слово) — игра не сломается, просто валидация будет как раньше. Console warning при первом запуске.

## Тестирование

| Сценарий | Ожидание |
|---|---|
| После setup-скрипта, в Console | `Big Dictionary check passed. Valid words: 466,000` (примерно) |
| MainMenu, дождаться анимации | В Console через 1-2 сек: `[Dictionary] Loaded 466558 validation words in 750ms.` |
| Войти в Game, собрать обычное слово (RAIN, STAR) | Засчитывается как раньше |
| Собрать длинное/редкое слово (DRACONIC, INTERPLAY, etc — если есть буквы на доске) | Засчитывается! Это слово точно НЕ из 401-словаря, но из большого |
| Очень редкое слово которого нет даже в 466k | `NOT IN DICTIONARY` (как раньше) |
| Полный цикл: MainMenu → Game → Game Over → MainMenu | Словарь не перезагружается — HashSet сохраняется на всю сессию |

### Способ проверить что большой словарь активен
1. В Game-сцене собери слово которое НЕ в стандартном 401-словаре, но есть в 466k. Например: `BISECT`, `KIOSK`, `PLUMBER`, `WAFFLE`, `ZEBRA`.
2. Если буквы есть на доске и слово засчитывается — большой словарь работает.
3. Если выдаёт `NOT IN DICTIONARY` для слова которое точно есть — проверь Console на errors про words.txt.

## Параметры

Никаких новых параметров в инспекторе. Всё автоматически.

Если нужно временно отключить большой словарь (например, для тестов) — удали `words.txt` из Resources и `Dictionary` fallback'нется на placement pool с warning в Console.

## Известные нюансы

- **Первый Validate после загрузки сцены может слегка фризнуть**, если Preload ещё не закончил (например, на очень медленном устройстве). После этого всё O(1).
- **Слова из words.txt с буквами F/J/K/Q/X/Z** валидируются, но генератор их не укладывает на поле (placement pool исключает эти буквы). То есть игрок может собирать слова через них, но они появляются только когда буквы рядом с placed-словами.
- **PlayerPrefs ключи** не изменились, существующие сохранения работают.
